# Проверка сайта: 27 октября 2026

Исправления подготовлены и проверены локально. Публикация на Vercel не выполнялась.

## Что исправлено

- На опубликованном сайте `/clients/optimized/sulpak.webp` возвращал `200`, а `/_next/image?...` — `404`. Все подготовленные WebP/AVIF теперь отдаются напрямую, включая логотипы и сканы отзывов. Для логотипов, отзывов и сцены настроен кэш на час с revalidation.
- Production canonical больше не указывает на localhost. Используется публичный домен Vercel или заданный `NEXT_PUBLIC_SITE_URL`; случайно скопированный локальный адрес заменяется публичным. Sitemap и JSON-LD используют тот же домен. Preview остаётся noindex.
- Добавлены safe area отступы для вырезов экрана. На узких телефонах логотипы размещены плотнее, WhatsApp-кнопка стала компактной и меньше перекрывает содержимое. Исправлены восстановление шапки после изменения размера окна и подсветка вложенных страниц услуг.
- Калькулятор принимает площадь 10–5000 м²: пустое поле восстанавливается при потере фокуса, нулевая смета не формируется. Поле имеет связанный label, подсказку и высоту 44 px.
- Отложенные формы сохраняют загрузочное состояние до готовности модуля. При сетевой ошибке появляются сообщение, повторная попытка и ссылка WhatsApp; восстановление проверено блокировкой JS-запросов.
- API вместо фиктивного `id=0` сохраняет заявку транзакцией и возвращает реальный ID после commit. Добавлены проверка телефона, обрезка пробелов, rollback и ответ `503` при недоступной БД. На Vercel SQLite запрещена, чтобы не выдавать временное хранение за постоянное.
- Next.js и ESLint-конфиг обновлены до 16.4.3, исправлены уязвимые транзитивные зависимости. Добавлен CI для бэкенда и фронтенда.

## Границы проверки и публикация

Проверки выполнены в Chrome с эмуляцией размеров и touch, без физических Android/iPhone и отдельного запуска Safari. Для 3D использован программный WebGL.

Для постоянного сохранения заявок API на Vercel требуется внешний PostgreSQL в `DATABASE_URL`. Тесты используют изолированные SQLite-базы; подключение к реальной production-БД и уведомления менеджеру не проверялись и не настраивались. Формы сайта продолжают готовить сообщения WhatsApp, которые отправляет посетитель.

После деплоя нужно проверить публичные картинки, canonical/sitemap и повторить `AUDIT_URL=https://guldar-group.vercel.app npm run test:e2e` с соответствующим синтаксисом переменной окружения для своей оболочки.
