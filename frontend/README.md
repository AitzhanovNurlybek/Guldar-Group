# GulDar Group

Next.js-сайт строительной компании в Алматы. Тексты, контакты, ставки калькулятора и ссылки WhatsApp хранятся в `src/lib/site.ts`; визуальное обновление их не меняет.

## Запуск

```powershell
cd frontend
npm install
npm run dev
```

Откройте http://localhost:3000. Для проверки производительности используйте production:

```powershell
npm run build
npm start
```

Если порт 3000 занят dev-сервером, можно оставить его работающим и запустить `npm start -- --port 3100`.

## Качество и анимация

Основной конфиг качества: `src/components/scene/quality.ts`.

| Уровень | Рендер | DPR | Частицы |
| --- | --- | --- | --- |
| low | Постер | 1 | 0 |
| medium | WebGL | до 1.25 | 0 |
| high | WebGL | до 1.75 | 18 в одном Points |

`webgl` включает сцену, `maxDpr` ограничивает разрешение, `particles` задаёт количество точек, `pointer` включает реакцию на мышь. `performanceBudget` содержит частоту общего ticker, длительность стартового FPS-теста, пороги качества и задержки загрузки. Экран до 767 px, reduced motion, save-data, ≤4 ГБ памяти или ≤2 логических ядра выбирают постер. Более мощные устройства дополнительно проходят тест кадров. При просадке FPS PerformanceMonitor уменьшает качество high → medium. Постобработка и динамические тени удалены целиком; их не требуется отключать на слабом GPU.

Скорость находится в `src/components/scene/animation-config.ts`: увеличение `scrollDuration` замедляет Lenis; уменьшение `damping` усиливает инерцию сборки; `roomRotation` задаёт общий угол. `headerDuration` и `railDuration` управляют навигацией. `scrub` сохранён для совместимости со старой конфигурацией; в новом общем цикле инерцию задаёт `damping`. Интервалы прилёта деталей находятся в массиве `parts` файла `RoomCanvas.tsx`, пороги подписей — в `SCENE_STAGES`.

GSAP загружается после первого показа страницы и обслуживает единственный JS rAF. Lenis работает с `autoRaf: false`. `scroll.ts` кэширует координаты при ResizeObserver/resize, не читая layout во время прокрутки. R3F использует `frameloop="never"` и ручной `advance` из этого же ticker. После остановки сборки GPU перестаёт получать кадры; вне экрана и в скрытой вкладке рендер останавливается. Значения прогресса передаются через mutable state, React обновляется только при смене стадии/режима.

Размер макета задаёт `.scene-visual` в `src/app/globals.css`: на десктопе высота `clamp(400px, 52svh, 560px)`, на телефоне — `clamp(280px, 94vw, 430px)`. Камера в `RoomCanvas.tsx` подстраивает угол обзора под пропорции блока, чтобы комната помещалась целиком. Масштаб постеров настроен отдельно селекторами `.scene-poster img` и `.scene-mobile-poster img`; мобильный параллакс остаётся на внешней обёртке.

## Модель и шрифты

Модель: `public/scene/room.meshopt.glb`, около 55 КБ, Meshopt. Она содержит объединённые части и два набора InstancedMesh. Освещение рассчитано в вершинах при экспорте, AO запечён в общую WebP-текстуру 256×256. В рантайме нет источников света, shadow maps или полноэкранных эффектов. Геометрия разбита по этапам сборки; это иллюстрация, а не портфолио выполненных работ.

```powershell
npm run model:build
```

Blender для этой сборки не нужен. Лёгкие постеры сохраняются в серверном HTML; на телефоне изображение находится в обычном потоке документа. Ручной выбор стадии на слабом устройстве загружает соответствующий сохранённый AVIF. Старый `SceneFrames.tsx` не импортируется главной страницей.

Manrope и Montserrat подключены через `next/font/local` с `display: swap`. Нужные кириллические и латинские глифы занимают около 39 КБ вместо 96 КБ четырёх исходных файлов. Оригинальные WOFF2 и OFL-лицензии сохранены. Для повторного субсеттинга нужен Python с `fonttools` и `brotli`; скрипт — `scripts/subset-fonts.py`.

## Проверки

После production-запуска на порту 3100:

```powershell
npm run audit:performance
npm run verify:interface
```

Скрипты используют установленный Chrome в headless-режиме. Для другого адреса задайте `AUDIT_URL`; для другого Chrome — `CHROME_PATH` (аудит). Lighthouse работает с стандартным мобильным профилем. Performance trace записывается при CPU 4×. Проверяются 375×812, 768×1024, 1440×900, 1920×1080 и 1440×650, reduced motion и отсутствие горизонтального скролла. Desktop-возможности в аудите принудительно выставлены в 8 ядер/8 ГБ, чтобы гарантированно проверить WebGL; это отмечено в JSON.

Результаты, HTML Lighthouse, trace и снимки лежат в `reports/`, папка исключена из Git. Сводка и ограничения измерений — в [PERFORMANCE.md](PERFORMANCE.md). Визуальный контракт — [DESIGN.md](DESIGN.md).
