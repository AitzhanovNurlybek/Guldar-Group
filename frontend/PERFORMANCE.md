# GulDar Group: production-проверка

Дата: 22 октября 2026. Сравниваются production-сборки (`npm run build`, `npm start -- --port 3100`), не dev. Исходные данные — `reports/before/summary.json`; итоговые — `reports/after/summary.json`. Lighthouse HTML и JSON, Chrome Performance trace и снимки сохранены рядом. Папка `reports` исключена из Git.

## Метод

- Lighthouse: стандартный мобильный профиль, симулированная сеть и CPU из конфигурации Lighthouse.
- Прокрутка: Chrome headless, CPU 4×, одинаковый сценарий вниз/вверх, длительность 5,5 с. Частота кадров браузера измеряется отдельно от частоты рендера WebGL.
- Desktop-проверка принудительно сообщает 8 ядер и 8 ГБ, чтобы пройти ветку WebGL даже на ограниченном хосте. Снижение качества по измеренным кадрам остаётся включённым. Это зафиксировано в JSON.
- Размеры: 375×812, 768×1024, 1440×900, 1920×1080 и 1440×650. Это эмуляция на одном компьютере, не замер физического слабого телефона.

Точные FPS браузера при прокрутке находятся в JSON (`viewports[].scroll.fps`). До оптимизации desktop-сценарий показывал 26,9 FPS. У новой сцены WebGL намеренно ограничен 60 кадрами/с; браузерный rAF на этом мониторе может показывать больше 100 FPS, поэтому эти две величины нельзя подменять друг другом. На мобильной ширине работает постер, а не WebGL.

**Оставшееся отклонение:** LCP 2,84 с превышает запрошенные 2,5 с примерно на 0,34 с. Цель по Lighthouse LCP не закрыта. Результаты не являются гарантией 60 FPS на любом ноутбуке или 30 FPS на физическом слабом телефоне. Неподтверждённые показатели не выдаются за достигнутые.

## Что тормозило и что изменено

1. Lenis имел свой autoRaf, R3F — отдельный цикл, общий scroll-helper — ещё один rAF. Теперь GSAP ticker обслуживает Lenis, кэш прокрутки, эффекты и ручной `advance` R3F. GSAP/Lenis загружаются после первого показа страницы.
2. На scroll читались координаты секций/anchor и записывались размеры canvas-слоя. Координаты и размеры теперь меняются только при resize/ResizeObserver; в кадре используются кэш и transform/opacity. Встроенное scroll-измерение R3F отключено.
3. Прогресс проходил через React state и пересоздавал дерево представления. Теперь mutable progress общий для комнаты и индикаторов; React обновляет только смену стадии/качества/режима.
4. Сцена имела индивидуальные меши, динамические тени, несколько источников света, HDR-проход и постобработку. Теперь геометрия объединена по частям сборки, повторения используют instancing, свет рассчитан в вершинах, AO записан в 256px WebP. Нет GPU-постобработки и realtime-света. Измерено 8 draw calls в скролл-фрагменте и 14 на ручном этапе 05.
5. Blur использовался на множестве поверхностей. Он оставлен только в шапке, как требует бриф. Остальные карточки используют статичный полупрозрачный фон и градиенты; анимации не меняют blur, тени или размеры.
6. Ниже первого экрана формы загружаются по IntersectionObserver и монтируются после короткой остановки прокрутки. Кириллица/латиница подключены через `next/font/local`; шрифты уменьшены с примерно 96 до 39 КБ. Лишняя предзагрузка ссылок меню отключена.

## Проверка интерфейса

`reports/after/interface.json` содержит результаты автоматического прохода: реальная область 375 px имеет clientWidth=scrollWidth=375; мобильное меню открывается, Escape закрывает его; все anchor-цели существуют; GLB стартует; этап 05 выбирается вручную; шапка скрывается вниз и возвращается вверх; калькулятор принимает 120 м²; WhatsApp-builder сохраняет номер `77786812931`; reduced motion показывает постер; клавиатура получает skip-link; ошибок JavaScript нет.

Основные пары текста/фона вычислены скриптом контраста: `#f2f5f3` / `#142d3c` — 13,01:1; вторичный `#9bb0bd` — 6,35:1; оранжевый `#ffad65` — 7,77:1. Фокус виден, элементы форм имеют цели не меньше 44 px. Дизайн-сканер не находит P0/P1; два P2 относятся к исходным текстам с разделителями «·», которые пользователь запретил переписывать.

## Delivery gate

- PASS — запуск и TypeScript: production-сборка генерирует все 14 страниц без ошибок.
- PASS — функциональность: проверки меню, стадий, форм, ссылок и клавиатуры записаны в `interface.json`.
- PASS — адаптивность: пять запрошенных состояний экрана без горизонтального скролла; мобильная кнопка меню полностью видна.
- PASS — направление: сохранённая фирменная сетка/палитра, общий контракт в `DESIGN.md`, сканер P0=0/P1=0.
- PASS — доказательства: нет новых выдуманных объектов, отзывов, статистики или обещаний; отклонение LCP указано выше.
